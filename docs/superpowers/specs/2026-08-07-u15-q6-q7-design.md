## U15: Remixer-name hybrid gate

### Problem

`_enrichment_title_match` uses `_title_stem` which strips ALL bracketed suffixes.
Two distinct remixes of the same track by the same artist (e.g., "Track Name
(Club Mix)" vs "Track Name (Extended Mix)") both stem to the same bare `track
name`. The artist gate doesn't catch it — remixes share the credited artist.
Measured: 9/18 search-matches wrong on sets with dense remix catalogs.

### Design

Keep the strict `_comparison_title` equality as the fast primary path. Replace
the `_title_stem` fallback with a hybrid gate that examines the Shazam title's
bracketed mix information:

1. **Named remixer** (e.g. "Track (Artist X Remix)") — gate on remixer identity
   against Beatport's `remixers` list and `mix_name`.
2. **Generic mix type** (e.g. "Track (Club Mix)", "Track (Extended Mix)") —
   compare mix types against Beatport's `mix_name`.
3. **No mix info** — fall back to the old stem comparison as last resort.

### New functions in `core/track.py`

Underscore-prefixed (following the existing convention in `track.py` — these are
helper functions, not a public API, but they are imported cross-module by
`identification.py`). The caller in `identification.py` calls one function.

#### `_extract_mix_info(title: str) -> dict`

Extract mix information from a title's bracketed suffix groups. Reuses the
existing `_decide_title_group` and `_SUFFIX_KEEP_RE` to identify remix-bearing
groups. Returns:

```python
{"remixers": list[str], "mix_type": str | None}
```

- Scans trailing bracketed groups via `_TRAILING_GROUP_RE`.
- A group containing a remix keyword (`_SUFFIX_KEEP_RE`) plus an identifiable
  name: strip the keyword, the remainder is the remixer name. Multiple
  remixer-bearing groups accumulate.
- A group containing only a generic mix label (`_SUFFIX_DROP_EXACT` members:
  "club mix", "extended mix", "original mix", "radio edit", "radio mix",
  "extended", "original") → `mix_type`.
- A group containing `_SUFFIX_DROP_PREFIXES` ("live at …") → ignored.
- Empty groups, feat-canonicalization groups, and unrecognized groups → ignored
  (they are not mix information).

#### `_any_remixer_in(shazam_remixers: list[str], bp_remixers: list[str] | None, bp_mix_name: str | None) -> bool`

True if any Shazam-extracted remixer name appears in the Beatport remixers list
(case-insensitive, word-boundary match — "John" must not match "Johnson") or in
the Beatport `mix_name`. The `mix_name` check catches cases where the remixer
is embedded in the mix name string rather than the structured `remixers` field.

#### `_mix_type_matches(shazam_mix_type: str, bp_mix_name: str | None) -> bool`

Compare the Shazam title's generic mix type against the Beatport `mix_name`.
Normalized, case-insensitive. Returns True if the mix types match, False
otherwise (and False when `bp_mix_name` is None — we can't verify without it).

#### `_enrichment_title_match` — updated

```python
def _enrichment_title_match(
    track_title: str,
    candidate_title: str,
    *,
    remixers: list[str] | None = None,
    mix_name: str | None = None,
) -> bool:
```

1. Strict `_comparison_title` equality → True (unchanged, fast path).
2. Extract mix info from `track_title` via `_extract_mix_info`.
3. If `shazam_mix["remixers"]` is non-empty → `_any_remixer_in(...)`.
4. Else if `shazam_mix["mix_type"]` is set → `_mix_type_matches(...)`.
5. Else → old stem fallback: `_title_stem(track_title) == _title_stem(candidate_title)`.

The new `remixers` and `mix_name` keyword args are optional with `None`
defaults — the function is also called from Spotify enrichment which doesn't
have remixer data, so the stem fallback is the only path for non-Beatport
callers (backward-compatible).

### Caller changes in `utils/identification.py`

`_beatport_acceptance_gate` already extracts `candidate["artists"]` and builds
the comparison title from `candidate["title"]` + `candidate["mix_name"]`. It
gains two lines: pass `candidate.get("remixers")` and `candidate.get("mix_name")`
to `_enrichment_title_match`.

### Acceptance

Re-run `scripts/measure_beatport_remix_matches.py` against all 5 measured sets
→ 0 MISMATCH. The existing dedup suite (d1–d21 in `test_track_matcher.py`) and
enrichment tests must pass unchanged.

### Edge cases

- **Shazam title has no brackets** → `_extract_mix_info` returns empty
  `remixers` and `None` mix_type → stem fallback (unchanged behavior).
- **Beatport record has no `mix_name`** (rare, but possible for "Original Mix"
  default) → `_mix_type_matches` returns False.
- **Beatport record has no `remixers`** → `_any_remixer_in` only checks
  `mix_name`.
- **Multiple remixers in Shazam title** (e.g. "Track (Artist X & Artist Y
  Remix)") → each remixer name is extracted; any one matching is sufficient.
- **Remixer name with "Remix" suffix** (e.g. "Artist X Remix") → the remix
  keyword is stripped before comparison; the extracted name is "Artist X".

## Q6: Lazy ffmpeg path resolution

### Problem

`YTDLPDownloader.__init__` and `MixcloudDownloader.__init__` call
`get_ffmpeg_path()`, which raises `FileNotFoundError` when ffmpeg is absent.
21 tests need a media binary installed; the class can't be constructed for
inspection.

### Design

Move `get_ffmpeg_path()` from `__init__` to the top of `download()`. Store
`self.ffmpeg_path` as `None` at init, resolve on first download call, cache
for subsequent calls.

```python
# In __init__:
self.ffmpeg_path: Optional[str] = None

# At the top of download():
if self.ffmpeg_path is None:
    self.ffmpeg_path = self.get_ffmpeg_path()
```

The `get_ffmpeg_path()` static method stays as-is — it's a pure PATH resolver
that only needs to exist at download time.

### What changes

| File | Change |
|------|--------|
| `downloaders/ytdlp.py` | Move `get_ffmpeg_path()` call from `__init__` to `download()` |
| `downloaders/mixcloud.py` | Same |
| `tests/` | No test changes needed — the 21 tests that currently need ffmpeg can now construct downloaders without it |

The CLI fail-fast check (`cli.py`) stays — it calls `get_ffmpeg_path()` before
constructing the downloader, which is the right place for a user-facing error.

## Q7: dev_cli tests

### Problem

`src/tracklistify/dev_cli/` — 1,362 lines across 10 files, zero test coverage.
Excluded from `testpaths`, coverage, and bandit. Two real bugs found by hand.

### Design

New `tests/test_dev_cli.py`. Focus on the three modules with logic worth
testing; the rest is thin glue over argparse/stdlib.

#### `config.py` — 3-4 tests

- `ToolsConfiguration` with a valid `tools.json` loads tools and `list_tools()`
  returns expected names.
- `ToolsConfiguration` with missing `tools.json` falls back to an empty config
  (the bug that was fixed by hand — the unreachable `ConfigurationError`
  early-exit blocked the fallback).
- `ToolsConfiguration` with a malformed `tools.json` degrades gracefully
  (empty config, no crash).

#### `commands/run.py` — 4-5 tests

- `RunCommand.run_shell_command` with `str` input (the common case).
- `RunCommand.run_shell_command` with `List[str]` input (the arg-mangling fix —
  spaced/quoted args survive as one argv element).
- `RunCommand.run_shell_command` with empty input.
- `RunCommand.run_shell_command` with a command that fails (non-zero exit).
- `RunCommand.run_shell_command` with a command that doesn't exist
  (FileNotFoundError).

#### `logging.py` — 2-3 tests

- `DevCliLogger.setup` constructs without error and a logger is accessible.
- `DevCliLogger.setup` with `debug=True` sets DEBUG level on the console
  handler.
- `DevCliLogger.setup` with `log_dir` creates the directory and log file.

#### `conftest.py` fixtures

- `tmp_tools_json` — writes a minimal `tools.json` to `tmp_path`, returns the
  path.
- `tmp_dev_cli_config` — constructs a `ToolsConfiguration` pointing at the temp
  tools.json.

### What changes

| File | Change |
|------|--------|
| `tests/test_dev_cli.py` | New file, ~12-15 tests |
| `pyproject.toml` | Remove `dev_cli/` from `[tool.coverage.run] omit` so coverage tracks it |

### Out of scope

- `cli.py` — argparse entry point, tested by running the CLI (integration).
- `commands/base.py` — abstract base class, tested through concrete commands.
- `commands/list.py` — thin wrapper over `subprocess.run`, tested through
  `run_shell_command`.
- `execution/` — the executor was deleted in the cheap batch; the `__init__.py`
  re-exports are minimal.
- `exceptions.py` — pure data classes, no logic.

## Regression risk

- **U15:** The `_enrichment_title_match` signature change is backward-compatible
  (new kwargs default to `None`). The stem fallback is preserved for
  non-Beatport callers and for titles with no mix info. The dedup suite
  (d1–d21) must pass unchanged — `_enrichment_title_match` is not used by
  dedup, only by enrichment.
- **Q6:** The downloader's `download()` method is the only path that reads
  `self.ffmpeg_path`. The CLI fail-fast check is unchanged. No behavior change
  for users with ffmpeg installed.
- **Q7:** New file, no existing tests to regress. The dev_cli module is
  read-only from the test's perspective.
